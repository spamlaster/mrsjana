# Minimal pairs audio

How the Minimal Pairs Therapy Center gets its recordings, and how Jana reviews them. Architecture and clinical rules are in `docs/minimal-pairs-spec.md`.

## Rules

- Generation calls OpenAI's paid API. Run it only when the project owner has approved that run. A dry run is always free.
- Recordings are marked reviewed with `--mark-reviewed` once Jana has approved them, one by one or all at once (`--mark-reviewed=all`). The project owner decides when that is; an agent runs it only when the project owner asks. Generation never marks anything reviewed.
- A new or regenerated recording always starts unreviewed.
- Listening Discrimination uses only reviewed recordings.
- The center never substitutes browser text-to-speech for a missing recording. `playWordRecording()` in `src/minimal-pairs/playback.ts` resolves `false`, and the activity shows the word without sound.
- The articulation recordings in `public/audio/words/` are never written by this command.
- Production games play reviewed recordings only. Preview mode (`npm run dev`) also plays unreviewed ones, so Jana can hear them in context, and the grown-up scoring bar says when a word has no recording or an unreviewed one.

## Settings

| Setting | Value |
|---|---|
| API | `POST https://api.openai.com/v1/audio/speech` |
| Model | `gpt-4o-mini-tts` (same as the articulation recordings) |
| Voice | `nova` (same as the articulation recordings) |
| Format | MP3 |
| Input | the word's `text` only |
| Key | `OPENAI_API_KEY` from the environment or `.env.local` (gitignored), as for `npm run voice` |

The instructions (in `scripts/minimal-pairs-audio.mjs`) ask for a warm teacher's voice in a General American accent, saying the word once, clearly, with full first and last sounds, the final consonant released without an added vowel, and nothing but the word. When a word has a `pronunciationHint`, the instructions add "Say the word meaning <hint>."

## Where recordings live

- Each lexicon word gets `public/audio/minimal-pairs/<word id>.mp3`. The file is named by the stable word id, never the spelling, so homographs cannot collide.
- To reuse an articulation recording instead, set the word's `audio` to its path, e.g. `audio: 'words/sun.mp3'`, after Jana has listened and agreed it suits the pair. Reused recordings are never regenerated.
- `src/minimal-pairs/content/audio-records.ts` records each recording's SHA-256 hash, where it came from, and who reviewed it. Only the script writes this file; a test fails if it is edited by hand.

## Commands

```sh
npm run voice:minimal-pairs:dry-run                         # report: what each word has and needs; no key, no API calls
npm run voice:minimal-pairs -- --dry-run --only=key,tea     # report for selected words
npm run voice:minimal-pairs -- --only=key,tea               # generate selected words that have no recording
npm run voice:minimal-pairs                                 # generate every word that has no recording
npm run voice:minimal-pairs -- --only=key --force           # replace a recording; clears its review
npm run voice:minimal-pairs -- --mark-reviewed=key,tea --by=Jana
npm run voice:minimal-pairs -- --mark-reviewed=all --by=Jana   # every word that has a recording
npm run voice:minimal-pairs -- --unreview=key
```

- Existing recordings are skipped unless `--force` is given, and `--force` requires `--only`.
- A word whose spelling has more than one pronunciation or meaning (the `heteronyms` list in the script, e.g. *tear*, *bow*, *wind*) is not generated until its lexicon entry has a `pronunciationHint`.
- A word with no recording of its own, but with an articulation recording of the same spelling, is not generated in a full run. The report suggests either reusing it or generating it with `--only`.
- Failed requests leave no partial file. Run the command again to retry.

## The missing-audio report

The dry run prints one line per word:

```
3 words: 1 reviewed, 1 unreviewed, 1 missing. 1 to generate.
            reviewed    key               minimal-pairs/key.mp3
            unreviewed  tea               minimal-pairs/tea.mp3
  GENERATE  missing     tie               minimal-pairs/tie.mp3
```

- **reviewed**: Jana approved this exact file.
- **unreviewed**: the file exists but has not been approved, or has changed since it was.
- **missing**: there is no file yet.

Notes under a line explain skipped words: a heteronym without a hint, a reuse candidate, or a reused recording.

`npm run test:minimal-pairs` also prints the asset readiness report per pair (`no-picture`, `no-audio`, `audio-not-reviewed`). Neither report fails the build.

## Reviewing recordings

1. Run the dry run and note the `unreviewed` words.
2. Play each file, e.g. `afplay public/audio/minimal-pairs/key.mp3` on a Mac, or open `/audio/minimal-pairs/key.mp3` while `npm run dev` is running.
3. Jana listens to both words of each pair one after the other and checks:
   - it is the intended word and meaning;
   - the contrast sound is clear and correct (/k/ vs /t/, /g/ vs /d/, /f/ vs /p/, /s/ vs /t/, /sh/ vs /t/, /th/ vs /t/ or /p/, /ch/ vs /t/, an s-blend vs its single consonant);
   - the first sound is not clipped, and the last consonant is audible without an added vowel;
   - it says only the word, in a natural, child-friendly voice, with nothing extra.
4. For each recording Jana approves: `npm run voice:minimal-pairs -- --mark-reviewed=<ids> --by=Jana`. If she approves the whole set, use `--mark-reviewed=all`.
5. For each one she rejects: add or adjust a `pronunciationHint` if the meaning was wrong, then regenerate with `--only=<id> --force` (after approval for the API run) and review again.
6. Commit the MP3s together with `audio-records.ts`.

If a reviewed file is later replaced by any other means, its hash no longer matches. The dry run then shows it as unreviewed, and `npm run test:minimal-pairs` fails until it is reviewed again or cleared with `--unreview`.
